## 1. 产品定位与权限

- 系统面向家庭私有多用户环境，不按公网开放社区产品设计。
- 只有明确授予 `ADMIN` 角色的账号可以访问管理端；首个管理员仅为现有用户。
- 家庭普通账号使用 `USER` 角色，不能登录管理端或调用管理 API。
- 支持两种账号创建方式：管理员创建临时密码账号；管理员生成一次性邀请供家庭成员注册。
- 邀请令牌单次使用、只保存哈希、24 小时过期、可由管理员撤销。
- 临时密码账号首次登录必须修改密码。

## 2. 前台核心行为

- 前台核心任务是查找影视内容并找到可用资源。
- 观看状态为唯一生命周期：未设置 → 想看 → 在看 → 看过；自定义片单与观看状态正交。
- 个人评分仅允许用于“看过”的内容，评分范围 1–10，步长 0.5，可附短评。
- 片单默认私有，可向已认证家庭成员只读共享；不提供匿名公网分享。
- 共享使用可撤销的不透明令牌，但访问者仍须完成家庭账号认证。

## 3. 搜索、目录与详情

- 搜索只检索结构化内容元数据，不把原始资源链接混入结果。
- 搜索字段至少覆盖标题、别名、演员、导演、年份和类型/题材。
- 搜索和目录筛选包括内容类型、年份、地区、类型/标签、是否有资源。
- 排序限定为相关度、最近更新和评分。
- 筛选、排序、分页和关键词必须反映在 URL 中，可刷新和分享后还原。
- 目录默认使用中等信息密度海报网格：桌面约 5–6 列，移动端 2 列。
- 短剧 UI 名称为“短剧”，客户端路径为 `/short`，内部类型统一为 `short_drama`。

## 4. 资源语义

- 资源默认优先级为磁力 → 网盘 → 在线。
- 在线资源按集展示。
- 网盘和磁力资源按单集、集数范围、整季、全集和其他进行分组。
- 在线资源优先在站内使用限制性 sandbox iframe 播放，同时提供显式外部打开和失败回退。
- 资源字段和分组由后端 DTO 明确定义，前端不得自行猜测集数或资源类型。

## 5. 爬虫与同步

- 本轮只稳定 `pkmp4` 单一来源，同时保留来源适配器扩展点。
- 不绕过验证码、登录、访问控制或反自动化挑战；遵守 robots、来源限速和 `Retry-After`。
- 自动增量同步可以更新元数据；资源必须先归一化和计算差异，再以事务方式更新。
- 来源临时不可用、抓取失败或页面解析不完整时，不自动删除现有内容或资源。
- 人工编辑采用字段级锁；锁定字段不被爬虫覆盖，抓取到的缺失/空值不得抹除旧非空值。
- 每种内容类型只保留一个自动调度；全量扫描是独立手工任务。
- 取消任务的语义是完成当前内容项后停止，并保存安全检查点。
- 陈旧且无真实活动进程的 `RUNNING` 任务迁移为 `INTERRUPTED`；历史日志保留。
- 历史资源只在完整备份后按内容、来源、资源类型和 normalized URL 精确去重。
- 数据迁移后的自动调度默认关闭，部署验收后再明确启用。

## 6. 视觉与设备

- 视觉方向为温暖森林、浅色优先，并完整支持深色模式。
- 动效由克制的功能微交互和首页有限品牌氛围组成；不得以持续动画干扰浏览。
- 所有动画必须支持 `prefers-reduced-motion`。
- 整体桌面优先，但前台移动端属于核心验收范围。
- 管理端移动端只需保证关键状态查看和安全操作；复杂批量编辑可以引导到桌面完成。
- UI 发布必须经过真实浏览器截图与交互验收；构建成功、HTTP 200 或容器健康不能代替 UI 验收。
- 浏览器验收在 TX5Pro 的独立 `film-forest-browser-audit` 工程中执行，不复用或修改其他项目的审计工程。

## 7. 时间、安全与数据默认值

- 新时间戳以 UTC 保存，API 使用带时区的 ISO-8601，界面按 `Asia/Shanghai` 展示。
- 历史时间语义无法由样本确定时停止迁移，不自行推测。
- 密码使用 BCrypt；遗留哈希采用登录成功后渐进升级，不保存或记录明文密码。
- 数据库、JWT 和外部凭据只通过运行时安全配置注入，不进入代码、Git、镜像、日志或报告。
- 修改共享 MySQL 端口、账号或网络前必须识别所有使用方并保留独立回滚路径。

## 8. 分阶段执行契约

- 按正式整改计划的 Phase 0–9 顺序执行，不得越级。
- 每个 Phase 开始时由 Codex 创建对应 Goal Mode 目标。
- 当前 Goal 只有在该阶段成功标准、验证和产物全部完成后才能标记完成。
- 每个 Phase 完成后停止并汇报，不自动进入下一阶段。
- 回滚与破坏性清理分离；删除镜像、备份、卷、旧表或历史日志必须另获明确授权。

## 9. Git 交付决策

- 四个真实仓库目录为 `client-ui`、`client-server`、`admin-ui`、`admin-server`。
- 四仓整改分支最初统一为 `remediation/film-forest-20260808`，均从各自执行前 HEAD 创建；该临时交付方式已由后续“仅保留 `master`”决策取代。
- admin-server 当前领先 `origin/main` 的两个本地提交必须保留，不得 reset、rebase 或改写。
- 四仓最终仅保留本地与远程 `master`，后续直接在 `master` 开发；删除其他分支前必须先把全部未合并、未推送提交纳入 `master` 并普通推送。
- `client-ui` 与 `admin-server` 的无共同祖先旧 `master` 使用 `ours` 历史合并：保留旧提交可追溯性，最终文件树采用整改分支。
- 项目通过根目录 `deploy/docker-compose.yml` 部署为单一 `film-forest` Compose project，关联 `client-ui`、`client-server`、`admin-ui`、`admin-server` 四个容器。
- 每完成一个独立需求点立即精确暂存、创建小提交并推送，少量多次。
- 提交遵循 Conventional Commits；type/scope 使用英文，标题和正文使用中文。
- 禁止 `git add .` 混入无关内容，禁止 force push、amend、rebase、hard reset 和跳过 hooks。
- 根目录不是 Git 仓库；每个四仓提交正文记录本文档当时的 SHA-256，发布归档保存本文档副本。
